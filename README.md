# Black Hole Highlights

Las Vegas Raiders news, scores, stats, injuries and odds for the Black Hole Highlights YouTube channel (@BlackHoleHighlights).
Fan-run. Not affiliated with the NFL or the Las Vegas Raiders. Never use official team logos or NFL marks; the data
feeds include logo and photo URLs, and the site deliberately doesn't render them (no publisher images either).

Live site: https://myintp.github.io/blackhole-highlights/ (GitHub Pages from the `main` branch, root folder).

## Pages
| Page | What it shows |
|---|---|
| `index.html` Home | What matters now: hero with next-game scoreboard, game week (pick, odds, injuries), top stories, stat of the day and key numbers, links into each area |
| `news.html` News | Every story, grouped by day; filter by topic, type (Official / Reporting / Opinion / Rumor), source and keywords. Filters live in the URL |
| `games.html` Game Center | Next game (live score during the game), pick, odds and line movement, both injury reports, tale of the tape, full schedule, milestones, results with box scores, a play-by-play breakdown (efficiency, scoring plays, biggest win-probability swings, drives) and recaps |
| `stats.html` Stats | AFC and AFC West standings, team stats with NFL ranks, advanced (EPA, success rate, QB EPA and CPOE), scheme tendencies (motion, play action, shotgun, blitz rate, box counts), player leaders, records since 2016 |
| `players.html` Players | A profile for every Raider who has played: box-score stats with NFL ranks, snap share, coverage allowed, pass rush, tackling, yards after contact, drops. `?p=<slug>` links to one player. Also the searchable roster (`#roster`) |
| `media.html` Media | Channel videos, official Raiders podcasts, ESPN Raiders video |
| `search.html` Search | Stories, players, games and pages (`?q=`) |
| `about.html` About | Purpose, editorial labels, data sources, live source status, contact |
| `404.html` | Not-found page (uses `<base href="/blackhole-highlights/">`) |

**Navigation.** Four areas (Home, Game Center, News, Team) plus About; on phones they sit in a bottom bar with More (the menu: Players, Videos, Search, About). Game Center, Team (Stats and Players) and News (Stories and Media) have a sticky section bar that shows one section at a time; the URL hash picks the section (`games.html#results`, or any element inside one such as `#odds` or `#g-<id>`), so links, sharing and Back work. Areas and sections are configured in `NAV` and `SECTIONS` in `scripts/build-pages.mjs`; the tab behaviour is `initSections` in `assets/js/app.js`.

Old anchors still work: `#news`, `#gameweek`, `#odds`, `#pick`, `#injuries` and `#stats` on the home page, and `MOVED` in `assets/js/app.js` redirects ones that moved (home `#schedule`, `#matchup`, `#milestones`, `#videos`, `#clips`; `stats.html#roster` and `#players`).

Every page also has the **game-week strip** under the header. It shows the next game with links to odds, injuries, matchup and pick, then the live score and clock, then the final with links to the box score and breakdown, plus bye, postponed and season-complete states. Next to it are this week's **AFC West scores** and the Raiders' division place. The logic is `stripState` in `assets/js/lib.js`: a game only reads "Live" when ESPN reports it live, and a live score older than 25 minutes shows its time.

The home page's **Stat of the day** picks one verified stat per Pacific day from the published data: a player stat with an NFL rank, a team-leader quiz, a team trend or a historical comparison. Each carries its source and date range, and "Save as image" draws a 1080x1350 card in the browser. See `statCandidates` and `statOfDay` in `assets/js/lib.js`.

## How it fits together
- **No build step for hosting.** GitHub Pages serves the committed files as they are. All URLs are relative, so the site works under `/blackhole-highlights/`.
- **Pages are generated from `src/`.** `src/layout.html` holds the shared head, header, menu and footer; `src/pages/*.html` hold each page's main content, starting with a JSON comment for title, description and script. Run `node scripts/build-pages.mjs` after editing `src/`; it also writes `sitemap.xml`. Don't edit the root `*.html` files directly.
- **Front end:** `assets/css/site.css` (design system), `assets/js/lib.js` (pure helpers, unit-tested), `assets/js/app.js` (menu, data loader with timeout and retry, stale-data notice, shared renderers), `assets/js/pages/*.js` (one per page). Plain ES modules, no framework.
- **Data:** everything factual renders from `data/*.json`, generated by `scripts/update.mjs`:

| File | Contents | Source |
|---|---|---|
| `site.json` | schedule, results, standings, next game (with live score and clock during games), this week's AFC West games (`week`), injuries, matchup, leaders, source status | ESPN |
| `odds.json` | current line, every hourly capture per game (`history`), closing lines with automatic ATS/over-under grading, season record | ESPN (DraftKings) |
| `news.json` | 180-day story archive with type, topic and duplicate grouping | Raiders.com, Review-Journal, ESPN, Silver & Black Pride, RaidersBeat (RSS) |
| `stats.json` | team stats with ranks, player leaders, roster; `advanced` and `tendencies` | ESPN; nflverse play-by-play and FTN charting |
| `games.json` | box score, line score, leaders and recap link per finished game (fetched once) | ESPN |
| `media.json` | channel videos, podcasts, ESPN video | YouTube, Raiders.com, ESPN |
| `history.json` | regular-season records since 2016 (fetched once) | ESPN |
| `players.json` | every player's season stats with NFL ranks, snaps and charting | nflverse (stats_player, snap_counts, PFR advanced stats) |
| `breakdown.json` | per finished game: unit efficiency, scoring plays, top win-probability swings, drives, field goals | nflverse play-by-play |
| `editorial.json` | **hand-written**: headline, lede, Pundit's Pick, keys, milestones | us |

- **Automation:** `.github/workflows/update.yml` runs the updater every hour at :07 and commits only when data changed. GitHub runs that cron late (every 3-6 hours on this repo), so from 18 hours before kickoff the job re-runs itself: hourly through the odds window, every 10 minutes during the game, until 4.5 hours after kickoff (`nextWait` in `scripts/lib/parse.mjs`). nflverse files are fetched at most every 12 hours (`scripts/lib/nflverse.mjs`, about 15 MB in all). `.github/workflows/ci.yml` runs the tests and checks on every push and pull request.
- **Reliability:** each feed has a timeout and retries with backoff. A feed that answers with nothing, or far fewer records than last time, counts as failed and keeps its last good data. The update job runs `scripts/check-site.mjs` (schema, record counts, timestamps) before committing, so a bad run publishes nothing. A failed feed keeps its last good data and is listed in `site.json` `sources`; pages then show a notice. Pages also show a notice when the update job hasn't succeeded for 2 hours around a game or 8 hours otherwise (via the public GitHub API), skeletons while loading, and a retry button if data can't load.

## Game day
See [docs/GAMEDAY.md](docs/GAMEDAY.md): the update schedule around a game, the first-game validation checklist and failure recovery.

## Odds timing
Lines are captured every hour from **12 hours before kickoff to 1 hour before**; the last run is aimed about 7 minutes before the window closes. The last capture is the closing line, used to
grade the Raiders against the spread and the total. Weeks 1-6 of 2026 come from public reports (the `baseline` in `odds.json`).

## Each game week (by hand)
Edit `data/editorial.json`: set `gameId` to `next.id` from `data/site.json`, then write the headline, lede, pick, keys and milestones.
Until then the site shows an automatic headline and "the pick drops before kickoff".

## Commands (Node 20+, no dependencies)
- `node scripts/update.mjs` refreshes data (`--force-odds` takes an odds snapshot outside the window, for testing only).
- `node scripts/build-pages.mjs` rebuilds pages and the sitemap from `src/`.
- `node --test tests/*.test.mjs` runs the unit tests (data parsing, news grouping, odds grading, search and filters).
- `node scripts/check-site.mjs` checks links, anchors, page metadata, data shape, secrets and placeholder text.
- `python -m http.server 8765` previews at http://127.0.0.1:8765/ (pages can't load data from `file://`).
- Run the hourly job on demand: GitHub, Actions tab, "Update data", "Run workflow".

## Advanced data limits
- nflverse updates the morning after games, so Players, Advanced and the play-by-play breakdown lag ESPN's box scores by up to a day.
- Coverage shells (Cover 2, Cover 3, man/zone) aren't in any free 2026 source (nflverse's participation file stops at 2024; PFF and Next Gen Stats are paid). The site shows what is charted for free instead.
- Charting (coverage allowed, pressures, missed tackles, drops) is Pro Football Reference's film review: a judgement, not a measurement.

## Configuration
- Optional repo secret `YT_API_KEY` (YouTube Data API v3). YouTube blocks its RSS feed for GitHub's servers, so channel videos only update automatically with this key. Everything else needs no keys.
- No newsletter: there's no mail provider yet, so the site's subscribe action is the YouTube channel.
- `og:url`, `og:image`, canonical URLs and the sitemap use `https://myintp.github.io/blackhole-highlights/`. Change `BASE` in `scripts/build-pages.mjs` and `src/layout.html` if the address changes.
- Share card: `assets/og-image.png` (source `assets/og-image.html`, render command inside).
